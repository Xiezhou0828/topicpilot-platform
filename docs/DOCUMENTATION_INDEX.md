## Authoritative handoff chain and report tiers

Use this handoff chain for new work and do not collapse its evidence levels:

`implementation/work order` -> `latest capability closure` -> `canonical closure` -> `release readiness/release report` -> `post-deploy verification`.

- An implementation report is authoritative for implementation facts and
  scoped validation only.
- A canonical-closure report is authoritative for canonical provenance,
  source-to-canonical SHA mapping, and accepted file ownership.
- A release report is authoritative for owner-authorized Production promotion
  and exact API/Web, migration/data, rollback, and revision evidence.
- A post-deploy report is authoritative for public/runtime verification.

A later report must not rewrite the status that an earlier report recorded at
its own audit time; it may link the later state and explain the transition.
Isolated PASS results are source evidence, not canonical or Production proof.
