## Phase C - Minimal Structural Role Authority audit

`InstrumentTopicRelation` is the best existing canonical carrier. It provides
canonical `topic_id` and `instrument_id`, `relation_version`, `valid_from`,
`valid_to`, and `relationship_metadata`.

Its `relation_type` is free-text and its current schema/model does not formalize
the required structural-role authority. It lacks an explicit constrained role
namespace, approval state/reference, source artifact id/hash, correction
sequence, supersession identity, and a formal approved as-of resolver. Existing
relation metadata is not authority.

The minimum formal record is:

```text
topic_id
instrument_id
structural_role
approval_state
effective_from
effective_to
authority_version
source_artifact_id
source_artifact_hash
approval_reference
correction_sequence
supersedes_authority_id
superseded_by_authority_id
lineage_hash
```

For `(topic_id, instrument_id, as_of)`, a resolver must return existence, one
of `REPRESENTATIVE`/`CORE`/`RELATED`, approval state, effective state,
supersession state, authority version, and lineage. Only approved, effective,
non-superseded records are consumable. Missing, unknown, conflicting, or
ambiguous authority fails closed; no relation order, current mapping,
frontend label, or dynamic market evidence may fill it.

```text
STRUCTURAL_ROLE_POLICY_READY=YES
STRUCTURAL_ROLE_AUTHORITY_READY=NO
AUTHORITY_READY=NO
IMPLEMENTATION_READY=NO
IMPLEMENTATION_BLOCKER=BLOCKED_BY_STRUCTURAL_ROLE_AUTHORITY_READ_MODEL
```

Closing this gap formally requires a bounded authority read model/resolver and
likely migration/schema/ORM support. That implementation is outside this
contract-only write set and was not started.

`structural_role=CORE` at the same relevant as-of. The projection itself must
be approved, effective, non-superseded, versioned, lineage-complete, and

`selected_for_score_projection`, `score_importance`, and projection approval/
version/effective metadata. It does not add a second Structural Role database
or taxonomy.
